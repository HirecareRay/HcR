# HCR 채용공고 전처리 Report v2

## 1. 개요

HCR 채용공고 전처리 v2는 캐치, 잡코리아, 인크루트에서 수집한 공고를 OCR과 LLM을 이용해 공통 JSON으로 변환하는 파이프라인이다.

v1의 단순 신입/경력 구분에서 발전해 공고, 직무, 트랙의 세 레이어를 분리하고 전처리 판단 근거를 함께 보존한다.

## 2. 주요 개선 사항

### 직무 단위 분리

LLM 프롬프트에 다음 원칙을 명시했다.

- 모집분야가 여러 개면 `jobs[]`를 여러 개 생성
- 서로 다른 모집분야의 위치, 전공, 요건, 업무를 혼합하지 않음
- 같은 표 행 또는 모집 블록의 정보만 같은 직무에 배치
- MMIS 설비 정비 등 별도 모집분야는 유사 분야와 합치지 않음

### 공통 정보와 트랙 정보 분리

- 공고 공통: `common`
- 직무 공통: `jobs[].responsibilities`, `jobs[].preferred_common`
- 신입 전용: `jobs[].tracks.newcomer`
- 경력 전용: `jobs[].tracks.experienced`

이를 통해 fit scoring이나 UI 표시 시 직무 공통 조건과 트랙별 조건을 합성할 수 있다.

### 품질 및 감사 로그

정규화 결과에 다음 정보를 남긴다.

- 삭제된 필드와 이유
- 신뢰도가 낮은 분류
- 파싱 및 OCR 경고
- 원본 파일과 행 번호
- OCR/LLM 사용 여부와 오류
- OCR 및 최종 입력 일부
- LLM 입력 해시

정제 결과가 잘못되었을 때 원문과 처리 과정을 역추적할 수 있다.

## 3. 처리 흐름

```text
data/raw
  -> 파일 읽기
  -> company_info 제거
  -> 상세 텍스트 및 이미지 URL 수집
  -> 이미지 다운로드 및 OCR
  -> OCR 품질 평가
  -> 상세 텍스트/OCR/페이지 텍스트 결합
  -> OpenAI JSON Schema 정규화
  -> 규칙 기반 후처리
  -> JSONL 및 캐시 저장
```

## 4. 캐시 전략

대량 데이터 재실행 비용을 줄이기 위해 세 종류의 캐시를 사용한다.

| 캐시 | 키 | 목적 |
|---|---|---|
| OCR 캐시 | 이미지 URL | 동일 이미지 OCR 재실행 방지 |
| LLM 캐시 | 스키마 버전, 모델, URL, 제목, 입력 텍스트 해시 | 동일 LLM 호출 방지 |
| 페이지 캐시 | 원공고 URL | HTML 재요청 방지 |

캐시는 5건마다 저장하고 프로그램 종료 또는 중단 시 `finally`에서 다시 저장한다.

실제 OpenAI 요청 상한은 두지 않으며, 테스트 시 `--limit` 또는 `--no-llm`을 사용한다. 캐시 결과는 재실행 시 API 호출 없이 재사용한다.

프롬프트 또는 LLM 스키마가 변경되면 캐시 키도 변경되어 오래된 구조화 결과가 잘못 재사용되지 않는다.

## 5. 데이터 품질 정책

### Headcount

- `headcount`: `"0명"`, `"00명"` 등 원문 표현 보존
- `headcount_value`: 실제 정수 변환값
- 미정 인원이나 0으로 가려진 표현은 `null`

### Deadline

- `YYYY-MM-DD` 사용
- 원문에 없는 시간대는 추정하지 않음
- LLM 결과가 비어 있으면 규칙 기반 날짜 추출 사용

### URL

- `source_url`: 원공고 주소
- `recruit_url`: 별도 지원 URL이 없으면 `source_url` 사용
- 이메일 주소는 URL 필드에 저장하지 않음

### OCR

OCR 원문이 깨져도 삭제하지 않고 로그 스냅샷에 남긴다. 다만 품질이 낮고 상세 텍스트가 충분하면 LLM 입력에서는 제외한다.

구조화 결과의 일관성을 위해 OpenAI temperature 기본값은 `0`으로 사용한다.
확인할 수 없는 문자열은 임의로 추정하지 않고 빈 문자열 `""`로 보존한다.

## 6. 알려진 한계

- 표가 복잡하거나 OCR의 행 순서가 깨지면 직무 간 정보가 섞일 수 있다.
- JavaScript 렌더링이나 봇 차단 사이트는 페이지 보완이 실패할 수 있다.
- 플랫폼별 컬럼명은 별칭 목록에 없는 경우 추가 작업이 필요하다.
- 동일한 신입/경력 정보가 원문 공통 조건인지 LLM 중복인지 자동으로 완전히 판별하기 어렵다.
- EasyOCR의 한국어 표 인식은 이미지 해상도와 레이아웃에 따라 품질 편차가 크다.

## 7. DB 적재 권장안

DB에는 `jobs_normalized_v2.jsonl`의 정규화 레코드를 적재한다.

DB 적재용 JSONL에는 정규화 데이터와 `raw_meta`만 남긴다.
`preprocess_log`, 삭제 정보, 낮은 신뢰도, OCR/입력 스냅샷은 별도 audit JSONL에 저장한다.
필요하면 audit JSONL을 별도 감사 테이블에 적재할 수 있다. OCR/LLM 캐시 JSON 자체는 DB 적재 대상이 아니다.

## 8. 검수 운영안

원본 산출물과 검수 산출물을 구분한다.

- 원본: `jobs_normalized_v2.jsonl`
- 검수본: `jobs_normalized_v2_reviewed.jsonl`
- 검수 이력: `manual_review_log.csv`

우선 검수 대상:

- `fallback`, `page_fetched`
- 저품질 OCR
- LLM 실패
- 빈 직무 배열
- 직무 분리 불명확
- 신입/경력 조건 중복

경고 개수만으로 품질을 판단하지 않는다. 연락처 필드 부재나 시간대 제거 같은 안내성 경고와 실제 직무 분리 오류를 구분해야 한다.
