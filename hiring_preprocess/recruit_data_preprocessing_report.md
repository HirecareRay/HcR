# 채용공고 데이터 전처리 리포트

작성일: 2026-06-17

## 주요 결정사항 요약

1. CATCH 전처리에서 회사명 원본 보존과 URL 기준 중복 제거를 우선 적용했다.
2. 회사명은 `company_original`, `company_clean`, `company_dart_query`로 분리해 관리한다.
3. DART API 연동 시 회사명은 검색 후보로만 사용하고, 최종 기준키는 `corp_code`로 둔다.
4. `SK(주) AX`처럼 중간에 법인 표기가 들어간 회사명은 임의로 제거하지 않는다.
5. 채용공고 중복 제거 기준은 회사명/제목/마감일이 아니라 `recruit_url`로 통일한다.
6. 잡코리아와 인크루트는 CATCH와 겉 컬럼은 유사하지만 `company_info` 구조가 달라 플랫폼별 파서가 필요하다.
7. 최종 산출물은 플랫폼별 정제 파일과 통합 파일 `all_jobs_clean.tsv`로 나누어 관리한다.
8. 매출액, 자본금, 영업이익 등 금액 정보는 억 단위 숫자로 정규화한다.
9. 이후 DART 재무지표는 수익성, 안정성, 성장성, 활동성 지표를 중심으로 연결한다.
10. 최종 목표는 채용공고와 기업 재무상태를 함께 해석하는 채용공고 기반 기업 리포트 생성이다.

## 개요

본 전처리는 여러 채용 플랫폼에서 수집한 공고 데이터를 하나의 표준 구조로 정리하고, 이후 DART API 기반 재무지표와 연결할 수 있도록 회사명과 기업 식별 정보를 안정적으로 관리하는 것을 목적으로 한다.

## CATCH 전처리

CATCH 데이터는 `company`, `title`, `job`, `detail_text`, `detail_img`, `detail`, `etc_info`, `company_info`, `url` 구조를 가진다. 기존 전처리에서는 회사명 정제와 중복 제거 기준에서 문제가 있었다.

- 회사명 정제: `SK(주) AX` 같은 이름이 손상될 수 있었음
- 중복 제거: `company_clean`, `title`, `deadline` 기준으로 URL이 다른 공고가 제거될 수 있었음

수정 후에는 원본 회사명 보존, DART 검색 후보명 별도 생성, URL 기준 중복 제거를 적용했다.

## 잡코리아 및 인크루트 확장

잡코리아와 인크루트는 CATCH와 겉 컬럼은 비슷하지만 `company_info` 내부 구조가 다르다. 따라서 하나의 전처리 흐름 안에서 플랫폼별 parser를 두고, 최종 결과만 공통 스키마로 맞추는 방식이 적합하다.

- 잡코리아: `basic_info`, `financial`, `benefits`, `location` 활용
- 인크루트: `basic_info` 중심으로 대표자, 업종, 기업규모, 매출액, 사원수 등 추출

## DART 연결 방향

DART API 연결 시 회사명은 매칭 후보로만 사용하고, 최종 매칭 후에는 `corp_code`를 기준키로 저장한다.

사용 예정 지표:

- 수익성지표: `M210000`
- 안정성지표: `M220000`
- 성장성지표: `M230000`
- 활동성지표: `M240000`

최종 리포트는 채용공고 요약, 기업 기본정보, 재무지표 요약, 채용과 재무상태 연결 해석으로 구성하는 것을 권장한다.
